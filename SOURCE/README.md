ایده یا پیشنهاد دوز/مار/فلپی را انتخاب کن تا مستقیماً وارد مربی و بوم همان بازی شوی. «ورود به کارگاه آزمایشی» و دکمه‌های هدر، مودال ورود/ثبت‌نام با ایمیل و رمز را باز می‌کنند؛ نام و جلسهٔ محلی پس از ورود ذخیره می‌شود. مربی سه‌گام با دکمه‌های کد، گام بعد و سؤال پاسخ می‌دهد. بازی اول رایگان است؛ بازی دوم paywall دارد و فعال‌کردن پرمیوم آزمایشی واقعاً چندپروژه‌ای را باز می‌کند. مسیرهای `#/studio/login`، `#/studio/signup`، `#/studio/coach`، `#/studio/preview` و `#/studio/games` قابل کلیک‌اند. حساب و اشتراک فقط محلی‌اند؛ AI آنلاین و پرداخت فعال نشده‌اند. بوم‌ها templateهای آموزشی اجرایی هستند، نه تولید خودکار هر ایده.

معماری، مدل‌های User/Game/Message/Step، مرز دسترسی و نگهداری/حذف در [docs/architecture.md](docs/architecture.md) و گزارش و روش انتشار در [docs/WEEK-3-DELIVERY.md](docs/WEEK-3-DELIVERY.md) آمده‌اند. ورودی، مسیر و پژوهش هفته‌های قبل و Auth واقعی قبلی حفظ شده‌اند.

# HPLGAME — کارگاه فارسی بازی‌سازی

معماری همان HTML/CSS/JavaScript است؛ بدون بازنویسی با فریم‌ورک. منطق اعتبارسنجی، فیزیک بازی و اتصال Supabase در ماژول‌های مستقل‌اند. رنگ‌های برند `#3C041F`، `#872341` و `#BE3144` و فونت Vazirmatn حفظ شده‌اند. CodePlay فقط مرجع وضوح معرفی و مسیر بوده و کد، تصاویر یا هویت آن کپی نشده‌اند.

دو مرحله واقعی رایگان وجود دارد: «اولین ستاره» و «پرش دقیق». «دنیای من» نمونه توسعه و غیرقابل اجراست. امتیاز اولیه صفر است. انتشار عمومی، ویترین تأییدشده، اشتراک و مربی آنلاین در این نسخه ارائه نمی‌شوند؛ رابط‌های نمایشی قبلی به‌عنوان خدمت واقعی نمایش داده نمی‌شوند.

## اجرای محلی

Node.js نسخه ۲۴ LTS با نسخه حداقل ۲۴٫۱۵ یا نسخه ۲۶ به بالا نصب کنید؛ CI از نسخه ۲۴ استفاده می‌کند:

```sh
npm ci
npm test
npm run build
npm run dev
```

آدرس: `http://127.0.0.1:4181/hplgame-webapp/`

`npm run dev` و `npm run preview` خروجی `dist` را سرو می‌کنند. بعد از تغییر کد دوباره build و صفحه را reload کنید. در صورت نیاز، `PORT=4182` را در محیط تنظیم کنید. برای بررسی صرفاً حالت مهمانِ سورس، `python -m http.server 4180` نیز قابل استفاده است؛ اتصال Auth در حالت توسعه باید از build اجرا شود تا SDK محلی در دسترس باشد. باز کردن فایل با `file://` برای ماژول‌ها پشتیبانی نمی‌شود.

## مدل کارگاه

بلوک‌ها «سرعت حرکت»، «ارتفاع پرش» و «امتیاز ستاره» را تنظیم می‌کنند. تنظیمات با اجرای تازه اعمال می‌شوند؛ ادامه بازی متوقف‌شده تنظیمات همان اجرا را حفظ می‌کند. بازی را با جهت‌ها و Space یا دکمه‌های لمسی آزمایش کنید. نزدیک ستاره پرش کنید، سپس به پرچم برسید. صرف زدن اجرا امتیاز نمی‌دهد. گرفتن ستاره، برخورد فیزیکی و رسیدن به پرچم لازم است. توقف زمان و موقعیت را حفظ می‌کند؛ شروع دوباره، زمان، امتیاز، موقعیت، سرعت عمودی و ستاره را reset می‌کند. هر مرحله حداکثر سه دقیقه فرصت دارد.

محدوده سرعت و پرش ۱ تا ۹ و امتیاز ستاره ۱ تا ۱۰۰ است. ارقام فارسی پذیرفته می‌شوند. ورودی نامعتبر کنار فیلد توضیح داده می‌شود و از اجرا جلوگیری می‌کند. تغییرات معتبر پس از ۷۰۰ میلی‌ثانیه ذخیره می‌شوند. واگرد/ازنو، بازگردانی با تأیید، و دانلود JSON پروژه وجود دارند. کد تنظیمات فقط نمای خواندنی بلوک‌هاست؛ کد دلخواه اجرا نمی‌شود.

## راه‌اندازی Supabase

۱. در داشبورد رسمی Supabase یک پروژه ایجاد کنید. منطقه میزبانی را با حوزه فعالیت و نیاز حریم خصوصی محصول انتخاب کنید. هزینه یا پلن پولی به‌صورت خودکار انتخاب نشده است.

۲. در SQL Editor، فایل `supabase/migrations/202610090001_hplgame.sql` را **فقط روی دیتابیس جدید** اجرا کنید. migration در یک transaction است. برای دیتابیس موجود، ابتدا schema و بکاپ را بررسی کنید؛ این migration ایجاد اولیه است و جایگزین یک مهاجرت داده بررسی‌شده نیست.

۳. Email provider را در Auth فعال و تأیید ایمیل را روشن کنید. حداقل طول رمز را روی ۱۲ بگذارید. SMTP معتبر، فرستنده تأییدشده و محدودیت ارسال کد را تنظیم کنید. قالب ایمیل باید `{{ .Token }}` را نمایش دهد تا کد یک‌بارمصرف به کاربر برسد. ورود کاربران قبلی با `signInWithOtp({ shouldCreateUser: false })` و تأیید با `verifyOtp` انجام می‌شود؛ ثبت‌نام، رمز عبور قوی و کد تأیید ایمیل را هم‌زمان لازم دارد.

۴. Auth → URL Configuration:

```text
Site URL: https://hosseinshaamani-creator.github.io/hplgame-webapp/
Redirect URL: https://hosseinshaamani-creator.github.io/hplgame-webapp/
Development redirect: http://127.0.0.1:4181/hplgame-webapp/
```

فلو PKCE فعال است. پیوند تأیید و بازیابی را در همان مرورگر/تب دارای نشست آغازگر باز کنید؛ verifier مربوط به PKCE در SessionStorage است. پس از رویداد بازیابی، رابط به `#/reset` می‌رود. باز شدن ایمیل در دستگاهی دیگر باید جداگانه بررسی شود؛ بدون verifier، کاربر باید فرایند را در مرورگر آغازگر دوباره شروع کند. فرم `reset` به‌تنهایی مجوز تغییر رمز ایجاد نمی‌کند؛ Auth باید نشست بازیابی معتبر بدهد.

۵. `.env.example` را به `.env` کپی و فقط این دو مقدار عمومی را وارد کنید:

```dotenv
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
APP_BASE_PATH=/hplgame-webapp/
```

`service_role`، کلید `sb_secret_`، رمز، اتصال مستقیم دیتابیس و access token را وارد نکنید. build کلید service role و کلید secret را رد می‌کند. `.env` و `.env.local` در Git نادیده گرفته می‌شوند. کلید عمومی با RLS امن می‌شود، نه با پنهان کردن آن. بدون تنظیم این مقادیر، صفحات عمومی دیده می‌شوند اما مسیر، پروژه، کارگاه و پیشرفت برای مهمان قفل می‌مانند.

۶. دوباره `npm run build` را اجرا کنید. مقدارهای عمومی در خروجی build قرار می‌گیرند. برای CI همان دو مقدار را در GitHub → Settings → Secrets and variables → Actions → **Variables** با نام‌های فوق تنظیم کنید؛ هیچ کلید خصوصی برای build لازم نیست.

۷. ثبت‌نام شامل نام کامل، موبایل ۱۱ رقمی با شروع `09`، ایمیل، رمز حداقل ۱۲ نویسه، تکرار رمز، نوع حساب و پذیرش قوانین است. موبایل به قالب خصوصی `+989xxxxxxxxx` تبدیل و unique می‌شود. ورود با موبایل یا پیامک فعال نیست؛ برای آن backend و سرویس OTP معتبر لازم است. اطلاعات تکراری با unique index و Auth کنترل می‌شوند.

## امنیت دیتابیس و ساخت مدیر

RLS روی `profiles`، `projects`، `progress`، `lessons` و `deletion_requests` فعال است. پروژه‌ها و پیشرفت فقط برای صاحبشان قابل خواندن‌اند. نقش از metadata ثبت‌نام گرفته نمی‌شود. دانش‌آموز فقط نام نمایشی، آواتار و وضعیت onboarding خودش را به‌روزرسانی می‌کند؛ permission ستون‌ها و trigger از تغییر نقش/شناسه جلوگیری می‌کنند.

`record_progress` در دیتابیس پیش‌نیاز و منتشر بودن مرحله را کنترل و XP را از درس می‌گیرد. XP تکراری جمع نمی‌شود. داده پروژه سمت دیتابیس هم validate می‌شود. `version` هر بار افزایش می‌یابد و update با نسخه قدیمی صفر ردیف تغییر می‌دهد؛ رابط آن را تعارض می‌داند. RPC مدیریت، `is_admin()` را سمت دیتابیس کنترل می‌کند و search را با پارامتر می‌گیرد. CSV در برابر فرمول مخرب محافظت می‌شود.

برای مدیر، ابتدا حساب معمولی بسازید و ایمیل آن را تأیید کنید. UUID را از Auth → Users بگیرید. فقط در SQL Editor با دسترسی مالک پروژه اجرا کنید؛ مقدارهای نمونه را با UUID و ایمیل **تأییدشده خودتان** جایگزین کنید:

```sql
update public.profiles
set role = 'admin'
where id = 'VERIFIED-USER-UUID'::uuid
  and id in (
    select id from auth.users
    where lower(email) = lower('YOUR-VERIFIED-EMAIL')
      and email_confirmed_at is not null
  );
```

سپس در `#/admin` وارد شوید. هیچ endpoint ارتقای نقش و هیچ رمز مدیر در frontend وجود ندارد. از حساب تست برای مدیر production استفاده نکنید. آخرین فعالیت نمایش‌داده‌شده، زمان فعالیت **آموزشی** است، نه تاریخچه کامل حضور یا آخرین ورود Auth. CSV فقط صفحه فعلی، حداکثر ۵۰ نتیجه را صادر می‌کند.

درخواست حذف حساب، یک درخواست خصوصی ثبت می‌کند. مدیر باید هویت صاحب درخواست را احراز و در Auth → Users حساب را حذف کند؛ روابط `on delete cascade` داده‌های وابسته را حذف می‌کنند. عملیات حذف واقعی در این پروژه با service role در frontend انجام نمی‌شود.

## حریم خصوصی و کاربران کم‌سن

حساب مستقل کودکان تا تکمیل فرایند واقعی و قابل اثبات رضایت والدین عرضه نمی‌شود. فرم فعلی فقط والد/بزرگسال را می‌پذیرد و metadata همان شرط را در trigger کنترل می‌کند؛ این یک اظهار کاربر است و **تأیید سن یا رضایت والدین قانونی نیست**. کاربران احراز‌هویت‌نشده می‌توانند محتوای عمومی را ببینند، اما کارگاه و پیشرفت برایشان قفل است. کشور فعالیت، سن مشمول، روش رضایت، راه تماس مسئول، مدت نگه‌داری، حذف بکاپ و شروط میزبان باید پیش از عرضه عمومی تعیین و متن قوانین/حریم خصوصی نهایی شود.

SessionStorage برای نشست Auth انتخاب شده است؛ گزینه «مرا به خاطر بسپار» ارائه نمی‌شود. رمز هرگز ذخیره نمی‌شود. LocalStorage فقط تنظیمات و پیشرفت مهمان را نگه می‌دارد. امنیت نشست SPA به جلوگیری از XSS وابسته است؛ اگر نشست با cookie از نوع HttpOnly لازم دارید، به backend/BFF واقعی نیاز است. مدیر رمز واقعی را نمی‌بیند.

## استقرار GitHub Pages

پروژه hash routing دارد؛ مسیرها مانند `/hplgame-webapp/#/learn` هستند و refresh به فایل اصلی می‌رسد. مسیر assetها نسبی است. توسعه محلی نیز پیشوند `/hplgame-webapp/` را پشتیبانی می‌کند.

۱. در مخزن GitHub، Settings → Pages → Source را روی **GitHub Actions** قرار دهید.
۲. تغییرات را به `main` ارسال کنید. `.github/workflows/pages.yml`، وابستگی‌ها را نصب، تست، build و artifact `dist` را deploy می‌کند.
۳. فقط URL و کلید public را در Variables بگذارید؛ برای انتشار صرفاً مهمان، خالی بمانند.
۴. Actions باید هر دو job را موفق نشان دهد. سپس لینک سایت، `#/learn`، `#/projects` و لینک‌های ایمیل را بررسی کنید.

اگر Pages هنوز از `main / root` منتشر می‌شود، سورس ماژولی با config خالی در حالت مهمان اجرا می‌شود. **فعال‌سازی حساب آنلاین باید از خروجی build باشد**؛ config عمومی و SDK در build تولید می‌شوند. workflow بدون تغییر Source به Actions، تضمین استقرار ندارد.

## تست‌ها

```sh
npm test
npm run build
npm run test:integration
```

تست‌های محلی شامل فیزیک واقعی، برد/باخت، توقف/reset، validation، XSS/CSV، تعامل DOM و اجرای SQL/RLS در PostgreSQL محلی PGlite هستند. JSDOM موتور چیدمان/رندر مرورگر نیست؛ موفقیت آن تأیید responsive یا تست سخت‌افزار لمسی نیست.

تست زنده فقط روی **Supabase تست و حساب‌های disposable** اجرا شود. این متغیرها را در محیط همان فرایند تنظیم کنید؛ آن‌ها را commit نکنید:

```text
HPL_TEST_SUPABASE_URL
HPL_TEST_ANON_KEY
HPL_TEST_A_EMAIL
HPL_TEST_A_PASSWORD
HPL_TEST_B_EMAIL
HPL_TEST_B_PASSWORD
```

هر دو حساب باید student و ایمیل‌تأییدشده باشند. تست پروژه موقت ایجاد و حذف می‌کند و login، isolation، role protection، conflict و بازیابی نشست دیگر را بررسی می‌کند. با `HPL_TEST_SIGNUP_EMAIL` و در صورت نیاز `HPL_TEST_SIGNUP_PHONE`، تست ثبت‌نام واقعی نیز فعال می‌شود؛ حساب ایجادشده و ایمیل تأیید را باید دستی مدیریت کنید. بدون این مقادیر، تست‌های live **skip** می‌شوند و به‌عنوان موفقیت آنلاین گزارش نمی‌شوند.

تأیید ایمیل، فراموشی رمز، SMTP، موبایل ۳۲۰/۳۷۵/۷۶۸/۱۰۲۴/دسکتاپ، zoom ۲۰۰٪ و ابزار کمکی باید با Chrome واقعی بررسی شوند. نتیجه و محدودیت اجرای فعلی در `docs/IMPLEMENTATION_REPORT.md` آمده است.
