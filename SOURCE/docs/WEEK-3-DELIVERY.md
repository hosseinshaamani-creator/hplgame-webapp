# تحویل فاز ۱، هفتهٔ سوم — ۳۰ اکتبر ۲۰۲۶

## فایل‌های ایجادشده

- `lib/prototype.js`: state پروتوتایپ، ورود و ثبت‌نام محلی، مربی و درس، canvas، بازی اول، modal قفل اشتراک، خروجی و حذف تأییدشده.
- `prototype.css`: چیدمان مربی/بوم/ورود/modal، واکنش‌گرایی و استفاده از پالت موجود.
- `tests/prototype.test.mjs`: دو سناریوی رفتاری شامل جریان اصلی و شرایط خطا.
- `docs/architecture.md`: وایرفریم متنی و انتقال وضعیت، معماری، مدل‌های فعلی و آینده، دسترسی، امنیت و نگهداری داده.
- `docs/WEEK-3-DELIVERY.md`: این گزارش.

## فایل‌های تغییرکرده

- `app.js`: افزودن مسیرهای `studio/*` و اتصال ماژول نمونه؛ مسیرهای محافظت‌شدهٔ قبلی حفظ شده‌اند.
- `lib/discovery.js`: فقط دو ورودی افزوده برای باز کردن کارگاه آزمایشی، در خانه و صفحهٔ ایده.
- `index.html`: بارگذاری استایل نمونه.
- `scripts/build.mjs`: کپی و نسخه‌گذاری محتوایی استایل جدید.
- `README.md`: معرفی جریان هفتهٔ سوم و مستندات.
- `app.js`، `index.html` و `prototype.css` در ریشهٔ مخزن: خروجی ساخته‌شده برای اجرای مستقل.

`npm test`: همهٔ ۲۰ تست موفق. پس از محکم‌کردن اعتبارسنجی state و انقضا، دو تست پروتوتایپ دوباره عبور کردند. build نهایی موفق است. تست بصری محلی دسکتاپ و موبایل ۳۷۵ پیکسل، تم تاریک، مسیر ورود تا بوم، پیشرفت درس و قفل اشتراک انجام شد. در عرض ۳۷۵، scrollWidth برابر ۳۶۰ بود و overflow افقی مشاهده نشد. دکمهٔ شروع مجدد پس از بازبینی موبایل اصلاح شد.

نسخهٔ عمومی در `https://hosseinshaamani-creator.github.io/hplgame-webapp/` بررسی شد: کارت ورودی هفتهٔ سوم، ورود با نام مستعار، انتقال همان ایده به مربی و باز شدن بوم نمایش داده شدند. اجرای بازی و حرکت با صفحه‌کلید روی سایت عمومی کار کرد. برای commit سورس و تست `0d84052` هر دو workflow «Verify HPLGAME source» و «Build and publish HPLGAME» موفق شدند. انتشار این نوبت از طریق بارگذاری مرورگر حساب مالک در main انجام شد؛ حساب خط فرمان برای مخزن همچنان خطای دسترسی 403 دارد. هیچ credentialی برای رفع این خطا استخراج یا به پروژه اضافه نشد.

## اجرای محلی و انتشار

در پوشهٔ `SOURCE` با Node.js 24 سازگار با `package.json`:

```sh
npm ci
npm test
npm run build
npm run preview
```

نشانی پیش‌فرض محلی: `http://127.0.0.1:4181/hplgame-webapp/`. مسیر نمونه: `#/studio/login`. ابتدا در صفحهٔ اصلی ایده را ثبت کن، سپس «ادامه در کارگاه آزمایشی» را بزن. برای انتخاب پورت دیگر، متغیر محیطی `PORT` را تنظیم کن.

برای Git با دسترسی مالک، از ریشهٔ مخزن:

```sh
git add SOURCE app.js index.html prototype.css
git commit -m "Build week-three interactive prototype and architecture"
git push origin main
```

Pages باید مانند تنظیم فعلی مخزن روی GitHub Actions بماند. workflow ریشهٔ `.github/workflows/pages.yml` در هر push به main ابتدا `npm ci`، تست و build را در SOURCE اجرا، سپس `SOURCE/dist` را با Pages منتشر می‌کند. workflow را از صفحهٔ Actions هم می‌توان دستی اجرا کرد. موفقیت job deploy و بارگذاری نسخهٔ جدید در سایت، معیار انتشار است؛ صرف commit به معنی انتشار موفق نیست. فایل workflow داخل SOURCE به تنهایی workflow مخزن محسوب نمی‌شود.

## مرز این تحویل

این خروجی پروتوتایپ تعاملی است. ورود آزمایشی حساب امن سروری نیست؛ مربی از پاسخ آماده استفاده می‌کند؛ بوم یک بازی ثابت است؛ پرداخت و ساخت بازی دلخواه با AI فعال نشده‌اند. Auth واقعی قبلی همچنان مستقل و نیازمند پیکربندی معتبر Supabase است. این موارد با برچسب در رابط مشخص شده‌اند. مصاحبه‌ها و بازبینی با کاربران واقعی هنوز باقی‌اند.
