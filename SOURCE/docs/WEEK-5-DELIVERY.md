# تحویل هفتهٔ پنجم HPLGAME

تاریخ بررسی: ۲۰ نوامبر ۲۰۲۶. فاز دوم، هفتهٔ پنجم رودمپ: ۲۹ آبان تا ۵ آذر.

## دامنهٔ پیاده‌سازی

ورود و ثبت‌نام از Supabase Auth واقعی استفاده می‌کنند؛ نسخهٔ آنلاین دیگر حساب یا پرمیوم محلی را معتبر نمی‌داند. ورود با کد ایمیل و رمز عبور، درخواست بازیابی و فرم تعیین رمز پس از رویداد معتبر PASSWORD_RECOVERY پیاده‌سازی شده‌اند. پروفایل قابل ویرایش است. ایده، پیام‌های مربی، گام آموزش و نتیجهٔ برد در learning_projects ذخیره و هنگام ورود دوباره بارگذاری می‌شوند.

مربی همچنان از درس‌ها و پاسخ‌های آماده استفاده می‌کند؛ AI مولد و پرداخت واقعی در این تحویل فعال نشده‌اند. تست پرمیوم در حالت آنلاین غیرفعال است.

## داده و دسترسی

Migrationهای جدید: `202611200003_learning_accounts.sql` و `202611200004_supervised_signup.sql`. هر دو در پروژهٔ موجود hplgame اجرا شدند؛ SQL Editor نتیجهٔ Success. No rows returned داد. migrationهای قبلی دوباره اجرا نشدند و داده‌ای حذف نشد.

سه نوع حساب پشتیبانی می‌شود: زیر ۱۸ سال با همراهی سرپرست، ۱۸ سال و بالاتر، و والد/سرپرست. در حالت زیر ۱۸ سال، سرپرست فرم را با ایمیل و موبایل خودش تکمیل می‌کند؛ نام و زمان اعلام همراهی به‌صورت فیلدهای غیرقابل‌ویرایش توسط client ثبت می‌شوند. این اعلام همراهی و تأیید مالکیت ایمیل، احراز رسمی سن یا هویت سرپرست نیست.

هر پروژه فقط برای صاحب حسابِ دارای ایمیل تأییدشده خواندنی است. نوشتن از طریق RPC معتبرشده با کنترل مالکیت، سقف پروژه، اندازهٔ پیام‌ها و نسخه انجام می‌شود. اولین بازی رایگان است؛ learning_entitlements تنها از سمت سرور قابل مدیریت است. دو درخواست هم‌زمان با قفل ردیف حساب مرتب می‌شوند؛ نسخهٔ قدیمی اجازهٔ بازنویسی خاموش ندارد.

صف ذخیرهٔ فرانت‌اند snapshot می‌گیرد، درخواست‌ها را به‌ترتیب ارسال می‌کند و پس از قطعی برای تلاش دوباره نگه می‌دارد. خروج هنگام ذخیرهٔ ناموفق متوقف می‌شود و بستن صفحه با تغییرات ذخیره‌نشده هشدار دارد. گفتگو و پروفایل ابری در حافظهٔ همین صفحه هستند؛ فقط نشست رسمی Supabase در LocalStorage پایدار می‌شود. رمز، کد ایمیل و کلید مدیریتی ذخیره نمی‌شوند. دادهٔ گفتگو تا حذف حساب/داده توسط فرایند مدیریت نگه داشته می‌شود؛ پاک‌سازی زمان‌بندی‌شده فعال نیست.

## نتیجهٔ تست‌ها

- npm test: هر ۳۷ تست موفق؛ صفر شکست و صفر skip.
- تست‌های صف: قطعی شبکه، حفظ snapshot، تغییر هنگام درخواست، تعارض نسخه و توقف هنگام خروج.
- تست PostgreSQL واقعی محلی با PGlite: سه migration، حساب‌های تأییدشده/تأییدنشده، RLS، سهمیه، نقش‌ها، پیام نامعتبر و مالکیت.
- تست یکپارچهٔ رابط با SDK و HTTP شبیه‌سازی‌شده: رمز نادرست/درست، درخواست بازیابی، جلوگیری از فرم بازیابی بدون لینک، ویرایش پروفایل، ذخیرهٔ مربی، ورود دوباره و بازیابی گام و پیام‌ها، جداسازی بعد خروج.
- ۳۲ تست قبلیِ ورود، مسیر ایده، پنج بوم، تم، کیبورد و ریسپانسیو همچنان موفق‌اند.
- تست گروه‌های ثبت‌نام: سه گزینهٔ حساب، جلوگیری از ثبت زیر ۱۸ سال بدون تأیید سرپرست در رابط و دیتابیس، ثبت زمان همراهی و جلوگیری از تغییر نوع حساب توسط client.
- بیلد با تنظیمات عمومی واقعی: online accounts: true.
- آزمون واقعی ثبت‌نام به سرویس Auth رسید، اما Gmail در لاگ سرور خطای `535 / BadCredentials` برگرداند. تنظیم رمز مخصوص برنامهٔ SMTP توسط صاحب حساب لازم است؛ بنابراین تحویل واقعی ایمیل و بازیابی رمز هنوز تأیید نشده‌اند. پیام مبهم رابط با پیام مشخص خطای سرویس ایمیل جایگزین شد.

## استقرار

GitHub Actions ابتدا npm ci، npm run test:ci و npm run build را اجرا می‌کند؛ فقط در صورت موفقیت Pages منتشر می‌شود. متغیرهای عمومی VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY در مخزن ثبت شدند. هیچ secret/service_role وارد فرانت‌اند نشده است.

Site URL تولید حفظ و مسیر /hplgame-webapp/staging/ به redirectهای مجاز افزوده شد. prepare:pages نسخهٔ آزمون را در /staging/ می‌سازد؛ این نسخه همان دیتابیس تولید را دارد و باید با حساب مخصوص آزمون استفاده شود. این یک دیتابیس staging مستقل نیست.

وضعیت انتشار این تحویل: خطای اولیهٔ درخواست مجوز بارگذاری با اتصال تازهٔ Chrome برطرف شد؛ ماژول‌ها، تست‌ها و migrationها در main ثبت شدند. انتشار سایر فایل‌ها ادامه دارد؛ موفقیت CI و بررسی زندهٔ نسخهٔ جدید هنوز باید ثبت شود.

## بازتولید بیلد و انتشار

از ریشهٔ مخزن:

```powershell
cd SOURCE
npm ci
npm test
npm run build
npm run prepare:pages
cd ..
git add SOURCE .github/workflows/pages.yml app.js index.html
git commit -m "feat: connect week 5 accounts and learning progress"
git push origin main
```

برای بیلد محلی، URL و publishable key در SOURCE/.env.local (نادیده‌گرفته‌شده توسط Git) تنظیم شوند. در این دستگاه Git به حساب دیگری وصل است؛ انتشار با مرورگرِ حساب مالک و اجازهٔ صریح کاربر انجام می‌شود. گذر از تست‌های خودکار جایگزین بررسی تحویل واقعی ایمیل نیست.
