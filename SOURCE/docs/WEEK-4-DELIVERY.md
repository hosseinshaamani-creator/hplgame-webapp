# تحویل فنی هفتهٔ چهارم HPLGAME

تاریخ بررسی نهایی: ۲۰ نوامبر ۲۰۲۶ — بازهٔ رودمپ: ۲۲ تا ۲۸ آبان

## محدوده و وضعیت

در فایل `HPLGAME_Coding_Roadmap_Final.xlsx`، شیت «رودمپ اجرایی»، هفتهٔ ۴ شامل «آزمون کاربردپذیری و نهایی‌سازی طراحی» و «راه‌اندازی مخزن، CI/CD و محیط‌های توسعه» است. درخواست اصلی، تکمیل کد و آماده‌سازی برای commit و push است؛ انتشار نیز در پیام بعدی کاربر مجاز شده است. کد در کامیت محلی `5f8b130` ثبت شد. تلاش برای `git push origin main` در ۲۰ نوامبر ۲۰۲۶ با خطای 403 انجام نشد؛ حساب Git فعلی `hossein-shamani-92` برای مخزن مجوز نوشتن ندارد. انتشار سپس با حساب مالک از طریق Chrome انجام شد: کامیت انتشار `109eda1` روی main ثبت شد؛ workflow «Verify HPLGAME source» شمارهٔ ۲۴ در ۱۵ ثانیه و «Build and publish HPLGAME» شمارهٔ ۲۲ در ۴۱ ثانیه موفق شدند. نسخهٔ آنلاین در ۲۰ نوامبر ۲۰۲۶ باز شد و پیشنهاد پازل، انتقال به مربی، اجرای بوم و انتخاب عدد ۱ با موفقیت بررسی شدند.

چهار بوم موجود (دوز، مار، فلپی برد آموزشی و ستاره) حفظ شدند. پازل اعداد نمونهٔ جدید و بوم پنجم است؛ این تفسیر، اختلاف عبارت «بوم چهارم» و «پنجمین بوم» در درخواست را با وضعیت واقعی کد رفع می‌کند.

## تغییرات قابل استفاده

- پیشنهاد سریع «پازل اعداد» در صفحهٔ اصلی، مستقیم وارد مربی و بوم پازل می‌شود؛ ایده اولین پیام کاربر است.
- مربی سه مرحلهٔ چیدن خانه‌ها، کنترل ترتیب و تشخیص برد دارد؛ دکمه‌های گام بعد، نمایش کد و سؤال پاسخ متناسب می‌دهند.
- پازل روی Canvas واقعی رسم می‌شود. اعداد ۱ تا ۶ باید به ترتیب انتخاب شوند؛ کلیک با مختصات مقیاس‌شده، لمس دکمه‌ها و کلیدهای لاتین/فارسی پشتیبانی می‌شوند.
- پیش از اجرا، حرکت پذیرفته نمی‌شود. انتخاب غلط راهنمای عدد بعدی می‌دهد؛ فقط پایان واقعی پازل برد را در LocalStorage ثبت می‌کند. شروع دوباره، دور بازی را بازنشانی می‌کند؛ سابقهٔ برد پروژه حفظ می‌شود.
- وضعیت دور فعال هنگام بازسازی پنل برای چت و هنگام تغییر تب حفظ می‌شود. پس از reload، پروژه، گفتگو، گام آموزش و سابقهٔ برد بازیابی می‌شوند؛ دور اجرای بوم از ابتدا شروع می‌شود.
- دکمهٔ رفتن به بوم، فوکوس را به Canvas می‌برد. پس از گام بعد و نمایش کد، فوکوس روی همان کنترل بازمی‌گردد؛ ارسال پیام و سؤال، ورودی پیام را فوکوس می‌کنند. آخرین پیام گفتگو در دید قرار می‌گیرد.
- راهنمای متصل با `aria-describedby`، اعلان وضعیت بازی و گام، فوکوس نمایان و کنترل‌های لمسی حداقل ۴۸ پیکسلی اضافه شدند. دوز با کلیدهای ۱ تا ۹، از بالا چپ به‌صورت ردیفی، قابل بازی است.
- RTL، فونت محلی Vazirmatn، هوپی، تم روشن/تاریک و پالت موجود حفظ شدند. مربی، حساب و پرمیوم کارگاه همچنان نمونهٔ محلی‌اند؛ AI آنلاین یا پرداخت واقعی اضافه نشده است.

## تست و شواهد

مجموعهٔ خودکار شامل **۳۲ تست** است: ۳۲ موفق، صفر شکست، صفر skip. شش تست نسبت به ۲۶ تست قبلی اضافه شدند. Canvas در JSDOM با context رسم شبیه‌سازی می‌شود؛ تعامل واقعی روی Canvas نیز جداگانه در Chrome بررسی شد.

| مورد | نتیجه و پوشش |
| --- | --- |
| محتوای واحد پازل | سه مرحله، کد هر مرحله، حدود گام و راهنمای سؤال |
| تعامل مربی | ایدهٔ اول، کد متناسب با مرحله، سؤال، گام بعد و فوکوس |
| بوم پازل | منع ورودی قبل از اجرا، انتخاب غلط، برد، restart و اجرای مجدد در میانهٔ دور |
| ورودی‌های پازل | دکمه‌ها، مختصات Canvas با اندازهٔ نصف، کلیدهای فارسی و لاتین |
| حفظ دور بازی | بازسازی پنل بعد از نمایش کد، ترتیب فعلی را حفظ می‌کند |
| ذخیرهٔ محلی | بازیابی پروژه، گفتگو، گام و برد پس از بارگذاری مجدد ماژول |
| جلسهٔ حساب | تست قبلی ورود/ثبت‌نام، بازیابی جلسه، خروج و جداسازی حساب‌ها موفق است |
| بوم‌های موجود | برد دوز با کیبورد، کنترل مار/فلپی/ستاره، برخورد و بردهای قبلی |
| سهمیه و paywall | تست قبلی جلوگیری از پروژهٔ دوم و پرمیوم آزمایشی موفق است |
| CI و امنیت بیلد | همهٔ تست‌های قبلی، از جمله منع secret/service-role در فرانت‌اند، موفق‌اند |

بررسی دستی Chrome روی نسخهٔ build شده در `127.0.0.1:4194/hplgame-webapp/`:

- پیشنهاد پازل به مربی و بوم متصل شد؛ انتخاب اشتباه ۳ پیش از ۱ راهنما داد؛ انتخاب ۱ تا ۶ پیام برد داد.
- عرض‌های ۱۴۴۰ و ۳۷۵ پیکسل بررسی شدند؛ عرض اسکرول صفحه از عرض viewport بیشتر نبود. دسکتاپ دو ستون و موبایل یک ستون داشت.
- در موبایل، دکمه‌های اعداد حدود ۹۳×۴۹ پیکسل بودند. بوم متناسب با عرض کوچک شد.
- هر دو تم، نمایش فارسی/RTL، فونت و هوپی بازبینی شدند؛ خطای JavaScript در لاگ ثبت‌شدهٔ تب مشاهده نشد.

## CI/CD

workflow تأیید در `.github/workflows/verify.yml` روی هر push به هر شاخه، pull request و اجرای دستی، در Node 24 این مراحل را انجام می‌دهد: `npm ci`، `npm run test:ci` و `npm run build`. workflow انتشار در `.github/workflows/pages.yml` روی push به main یا اجرای دستی، همین بررسی‌ها را انجام می‌دهد و تنها پس از موفقیت build، artifact پوشهٔ `SOURCE/dist` را با دسترسی‌های Pages/OIDC منتشر می‌کند. هر job حداکثر ۱۵ دقیقه زمان دارد. هر دو workflow در **ریشهٔ مخزن** فعال می‌شوند؛ نسخهٔ قدیمی داخل `SOURCE/.github` نقطهٔ اجرای GitHub نیست.

اسکریپت‌ها در `SOURCE`:

```powershell
npm ci
npm test
npm run test:unit
npm run test:integration
npm run test:ci
npm run build
npm run preview
```

`npm test` و `test:ci` کل ۳۲ تست را اجرا می‌کنند. `test:unit` مدل، موتور بازی و درس‌های پازل را بررسی می‌کند. `test:integration` سناریوهای کارگاه، پوسته و هفتهٔ ۴ را بدون سرویس خارجی اجرا می‌کند. تست اتصال واقعی Supabase با `npm run test:live` جداست و به متغیرهای `HPL_TEST_*` و حساب‌های تست نیاز دارد؛ در این تحویل روی سرویس واقعی اجرا نشده و جزو ۳۲ تست موفق نیست.

## آماده‌سازی commit و انتشار

ابتدا در ریشهٔ همین مخزن diff را مرور کن. دستورهای زیر تغییرات مشخص این تحویل را انتخاب می‌کنند و خروجی ریشه را هم ثبت می‌کنند:

```powershell
git -c core.whitespace=cr-at-eol diff --check
git diff --stat
git add .github/workflows/verify.yml .github/workflows/pages.yml SOURCE/lib/numbers.js SOURCE/lib/prototype.js SOURCE/lib/discovery.js SOURCE/prototype.css SOURCE/tests/numbers.test.mjs SOURCE/tests/week4.test.mjs SOURCE/tests/discovery.test.mjs SOURCE/package.json SOURCE/README.md SOURCE/docs/WEEK-4-DELIVERY.md app.js index.html prototype.css
git diff --cached --stat
git commit -m "feat: deliver week 4 puzzle, accessibility and automated checks"
git push origin main
```

GitHub → Settings → Pages → Build and deployment باید روی GitHub Actions باشد. پس از push، موفقیت هر دو workflow و job انتشار را بررسی کن؛ سپس سایت `https://hosseinshaamani-creator.github.io/hplgame-webapp/` را باز کن. تغییر نسخهٔ assetها در HTML بیلد، بارگذاری نسخهٔ تازه را برای بازدیدکنندهٔ قبلی ممکن می‌کند. اگر push خطای 403 داد، حساب Git باید برای همین مخزن مجوز نوشتن داشته باشد؛ push ناموفق به معنای انتشار نیست.
